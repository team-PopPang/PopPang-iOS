# PopPang PR Writing Style

이 문서는 `auto-pr`가 기존 PopPang PR 문체를 재현하기 위한 기준이다.

## 제목

기본 원칙:

- 사용자가 PR 제목을 따로 요구하지 않으면, 브랜치나 사용자 요청에서 찾은 이슈 번호의 GitHub 이슈 제목을 그대로 PR 제목으로 사용한다.
- `gh issue view <issue-number> --json title`로 가져온 제목을 임의로 요약하거나 문체를 바꾸지 않는다.
- 아래 형식과 예시는 이슈 제목을 가져올 수 없고 사용자가 "관련 이슈 없음"을 명시한 예외 상황에서만 사용한다.

직접 작성 형식:

```text
[type] 한글 작업 요약
```

자주 쓰는 서술:

- `...를 도입한다`
- `...를 추가한다`
- `...를 분리한다`
- `...로 재구성한다`
- `...문제를 해결한다`
- `...를 정리한다`

기존 제목 예:

- `[feat] AdMob 네이티브 광고를 도입한다`
- `[feat] 관리자 팝업 요청 리스트를 도입한다`
- `[fix] BottomSheet의 런타임 duplicate class 경고와 크래시 문제를 해결한다`
- `[refactor] AdMob 네이티브 광고를 모듈로 분리한다`
- `[refactor] Modular Architecture로 재구성한다.`
- `[test] 코드 리뷰를 위한 CodeRabbit 설정`

## 변경 사항 섹션

기본은 bullet 중심이다.

```text
- <대상>을 <무엇>하도록 구현했습니다.
- <기존 구조>를 <새 구조>로 변경했습니다.
- <파일/모듈>에 <역할>을 추가했습니다.
- <화면/흐름>에서 <동작>하도록 연결했습니다.
- <문서>에 <내용>을 문서화했습니다.
```

기술 설명은 간결하지만 구체적으로 쓴다.

- 모듈명, 파일명, 타입명은 backtick으로 감싼다.
- 단순 "수정했습니다"보다 무엇이 바뀌었는지 쓴다.
- 여러 레이어가 바뀌면 `Feature`, `Coordinator`, `Domain`, `Data`, `Docs` 흐름이 드러나게 쓴다.

## 상세 섹션

아래 상황이면 `## ✏️ 변경 사항` 아래 또는 `## 🔥 추가 설명`에 하위 섹션을 추가한다.

- 크래시나 링크 문제: `### 문제 원인`, `### 해결 내용`, `### 검증한 내용`, `### 추가 확인 필요`
- 아키텍처 변경: `### 구조 변경`, `### 영향 범위`, `### 측정 조건`
- 광고/SDK/설정 변경: `### 설정`, `### 문서화`, `### 추가 확인 필요`
- 성능/빌드 비교: 표를 사용한다.

## PR 유형 체크 기준

여러 유형이 섞이면 복수 체크한다.

- 새 화면, API 흐름, 사용자 기능: `Feature`
- 버그, 크래시, 링크/런타임 문제: `Fix`
- 긴급 배포 차단 문제: `Hotfix`
- 설정, 템플릿, 운영 자동화: `Chore`
- 구조 개선, 모듈 분리, 책임 이동: `Refactor`
- 테스트 추가/수정: `Test`
- README, Docs, AGENTS, 스킬 문서: `Docs`

## 관련 이슈

브랜치명 `feature/#15`처럼 이슈 번호가 있으면 아래처럼 쓴다.

```text
- close #15
```

여러 개면 bullet을 여러 줄로 작성한다.

## 스크린샷

UI 변경이 없거나 자료가 없으면 템플릿 기본 placeholder를 유지한다.

```text
|기능|스크린샷|
|:--:|:--:|
|GIF|<img src = "" width ="250">|
```

사용자가 이미지 URL을 제공하면 `IMG` 또는 `GIF` 행에 넣는다.

## 추가 설명

리뷰어가 알아야 하는 내용만 쓴다.

예:

- 기존 구현을 삭제하지 않고 `Legacy`에 보관한 이유
- 검증한 명령과 결과
- Release/TestFlight에서 추가 확인이 필요한 사항
- 문서나 설정의 후속 작업

## 피해야 할 것

- CodeRabbit 자동 요약을 사람이 작성한 것처럼 추가하지 않는다.
- diff를 그대로 장황하게 나열하지 않는다.
- 확인하지 않은 테스트를 체크리스트에서 체크하지 않는다.
- 비밀값, 토큰, `.xcconfig` 실제 값, `GoogleService-Info.plist` 내용을 본문에 쓰지 않는다.
