# 정보 구조 만들기

정보 구조는 독자가 적은 노력으로 내용을 이해하게 하는 배치예요. 쓰는 사람이 생각한 순서가 아니라 읽는 사람이 목표에 닿는 순서로 놓아요.

## 구조를 고치기 전에 적어 둘 것

- 이 문서를 여는 독자의 대표 질문
- 다 읽은 뒤 독자가 할 수 있어야 하는 일
- 가장 중요한 섹션과 없어도 되는 섹션
- 다른 문서로 뺄 주제

이 답 없이 구조를 바꾸면 섹션 위치만 섞이기 쉬워요.

## 한 페이지에서는 하나만 다뤄요

한 페이지에는 핵심 목표를 하나만 둬요. 질문과 개념을 한꺼번에 넣으면 독자가 무엇을 가져가야 할지 알기 어려워요.

- 서로 다른 질문에 답하는 섹션이 섞여 있으면 나눠요.
- 설치, 개념, API 표, 오류 해결이 한 문서에 다 있으면 나눌 때예요.
- 제목이 `####`까지 계속 깊어지면 문서를 나눌지 검토해요.
- 상위 문서에 개요를 두고 하위 상세 문서로 연결해요.

[한국어 윤문 원칙](../korean-editing.md)도 이렇게 나눴어요. 원칙 문서에는 규칙과 요약을 두고, 문체·문서 유형·정보 구조·문장 다듬기는 하위 문서로 뺐어요.

판단할 때는 이렇게 물어요.

- 이 페이지에서 독자가 얻어 갈 한 가지는 무엇인가요?
- 제목을 한 문장으로 풀어도 자연스러운가요?
- 일부를 다른 문서로 빼면 전체를 이해하기 쉬워지나요?

## 가치를 먼저 보여줘요

기능이나 세부 설정보다 독자가 얻는 것을 먼저 보여줘요. 독자는 "왜 필요한가"와 "읽으면 무엇이 달라지는가"를 먼저 알고 싶어 해요.

| 안 좋은 흐름 | 좋은 흐름 |
| --- | --- |
| 기능 설명 → 옵션 → 예외 → 왜 필요한지 | 어떤 문제를 푸는지 → 무엇을 얻는지 → 어떻게 쓰는지 → 세부 옵션과 예외 |

- 첫 문단에 이 문서가 푸는 문제를 적어요.
- 개요나 목표에 읽고 나면 할 수 있는 일을 적어요.
- 작은 제약은 뒤 섹션으로 보내요.

## 제목은 짧고 구체적으로 써요

제목만 훑어도 내용이 보여야 하고, 검색으로도 찾을 수 있어야 해요.

- 핵심 키워드를 넣고, 30자 안쪽을 기준으로 삼아요.
- 대상과 행동이 드러나게 써요. 예: `인증 헤더 설정하기`, `업로드 실패 원인 점검하기`
- `소개`, `기타`, `고급 기능`, `팁`처럼 내용이 보이지 않는 제목은 피해요.
- 같은 수준의 제목은 같은 형식과 리듬으로 맞춰요. 형제 제목을 나란히 놓고 확인해요.

## 개요를 빠트리지 않아요

개요만 읽어도 "나에게 필요한 문서인가"를 판단할 수 있어야 해요. 개요에는 다루는 대상, 읽으면 할 수 있는 일, 필요한 사전 조건, 큰 흐름을 담아요.

- 2~4문장이나 짧은 목록으로 끝내요.
- 기술 배경보다 독자가 얻는 것을 먼저 적어요.
- 역사부터 길게 쓰지 않아요.

> 이 문서는 OAuth 로그인 흐름을 설정하는 방법을 설명해요. 다 읽으면 인증 제공자 등록, 리디렉션 URI 설정, 콜백 처리까지 한 번에 구성할 수 있어요. 시작하기 전에 클라이언트 ID와 클라이언트 시크릿을 준비하세요.

## 예측할 수 있게 해요

비슷한 문서는 같은 뼈대를 써요. 독자가 같은 위치에서 같은 종류의 정보를 찾게 해요.

- 같은 수준의 제목은 같은 형식을 따라요.
- 개념 → 절차 → 예시 → 확인 같은 흐름을 문서마다 같게 유지해요.
- 표, 코드 블록, 체크리스트 위치를 맞춰요.

이런 구조는 다시 봐요: 어떤 페이지는 개요가 있고 어떤 페이지는 없어요. 예시가 어떤 페이지에서는 먼저, 어떤 페이지에서는 마지막에 나와요. 같은 수준의 제목이 문장과 명사구로 섞여 있어요.

## 자세히 설명해요

독자는 이 문서를 처음 읽을 수 있어요. 새 개념을 생략하거나 조건을 빼면 독자가 추론으로 빈칸을 메워야 해요.

- 새 개념은 처음 나올 때 1~2문장으로 정의해요.
- 왜 알아야 하는지, 어디에 쓰는지 함께 적어요.
- 입력, 상태, 시간에 따라 결과가 달라지면 그 조건을 밝혀요.
- 예제와 설명을 이어서 써요.
- 배경은 핵심을 흐리지 않을 만큼만 쓰되, 추론이 필요 없을 만큼은 충분히 줘요.

## 여러 문서로 나눌 때

- 상위 문서가 전체 개요를 맡아요.
- 상세 문서는 질문 단위로 나눠요.
- 페이지마다 역할을 하나씩만 둬요.
- 다음에 읽을 문서로 자연스럽게 연결해요.

## 구조를 고치는 순서

1. 문서의 핵심 목표를 한 문장으로 적어요.
2. 목차에서 핵심 목표와 관계없는 섹션을 표시해요.
3. 개요를 먼저 써요.
4. 제목만 읽어도 흐름이 보이게 다시 배열해요.
5. 세부 설명, 배경, 예시를 알맞은 자리로 옮겨요.
6. 다른 문서로 뺄 내용을 나눠요.

## 확인할 것

- 한 페이지에 목표가 하나인가요?
- 첫 화면에서 가치를 먼저 전하나요?
- 제목이 짧고 구체적인가요?
- 개요가 문서 목표를 분명하게 보여 주나요?
- 비슷한 문서끼리 구조를 예측할 수 있나요?
- 새 개념에 필요한 설명이 붙어 있나요?
- 세부 정보가 핵심 정보보다 앞에 오지 않나요?
